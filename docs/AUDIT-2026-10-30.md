## Recuperación y seguridad

Caller con cron alternativo y workflow_run de CI en main, más dispatch manual.
Reutiliza supervisor con permisos idénticos de lectura, sin dispatch API, PAT nuevo,
servicios externos, auto merge ni escrituras de estado. Se pasa únicamente el
secreto opcional ya soportado para conservar compatibilidad multiproyecto.
No ejecuta código del PR ni descarga artefactos. Guardas verifican rama, origen y
evento; checkout sin persistir credenciales. No se heredan todos los secretos.

El grupo global de concurrencia serializa ambas vías; gate se evalúa dentro del
bloqueo. Un paso de inspección exitoso reciente en cualquiera de los workflows
es recibo persistente; otros pasos, skips y fallos no cuentan. Periodo mínimo
móvil de diez minutos desde finalización; sin catch-up masivo. Timeout de cuatro
minutos limita bloqueos. Interrupciones vuelven a ser elegibles en el próximo
trigger. Errores API o historial incompleto fallan cerrados. Las lecturas repetidas
son idempotentes; no se garantiza exactly-once si la API aún no refleja el recibo.
GitHub puede reemplazar runs pendientes; no hay FIFO garantizado.

Cron alternativo y eventos CI reducen dependencia de un único disparador, pero
comparten GitHub: sin eventos entrantes no existe garantía de recuperación ni
SLA de 15 minutos. No contar schedule del caller como entrega del cron nativo.
